# Talk track: Cedar act.sub Lab

One-liner: "Does Privilege's Cedar policy really match on the agent's act.sub claim? We measured it on a real tenant; this lab replays the shape so you can see it."

## The walk (about 5 minutes)

1. **Point at the banner.** The runs are simulated: a mock token and a mock door. The door is an evaluator of one rule shape, not a Cedar engine, and it decides nothing real. (10 seconds.)
2. **Step 1, baseline.** No policy. The same token calls CountTool and ListIndexTool and both are allowed.
3. **Step 2, add two Active policies.** Read the Cedar out loud: forbid the tool unless the token's claims have act.sub and it contains the agent. Policy A names the token's own agent, policy B names a different one. Only Active is enforced.
4. **Step 3, same token, two tools.** CountTool is allowed, ListIndexTool is refused: `action denied by policy: ListIndexTool requires act.sub to be agent-b-example`, JSON-RPC -32600. Open "What the mock door did (simulated)" to show the two checks the mock computed: sign-in passed, the policy refused. It is the lab's mock, not Privilege.
5. **Step 4, remove the policies.** Back to baseline. The policy was the only change.
6. **Extras (all simulated, none measured).** If act were emitted as the text "{}", the rule is believed to find no act.sub and so never to match (UNVERIFIED; act should be an object). With no token, this mock refuses at sign-in (the 401 wording is copied from the sibling lab, not measured). Per the Privilege console documentation, a Candidate policy is not enforced (not re-run here, UNVERIFIED).
7. **Scroll to the measured card.** This part is not a mock run: it is what happened on a real tenant on 2026-11-16. In one run the first poll, about 7 seconds after the policies were created, already showed the refusal. That is one observation, not a measured or guaranteed propagation time. Read the "Not measured" list aloud, then the UNVERIFIED claims card below it.

## If asked

- **"Is this a real Cedar engine?"** No. The mock evaluates one rule shape. The Cedar text shown is generated by this lab from the template's shape, with example ids. Only the `contains(...)` test inside `forbid ... unless` was read from the real tenant; the lines around it (`@reason`, action, resource, the `when` clause, the `has` guard) are copied from the sibling lab and are UNVERIFIED. No observation of the controller's own checks on the text is recorded.
- **"Did you test two different agents?"** Not for real. The one real client always carried a single act.sub; the refusal came from a policy naming a different agent.
- **"Is there a simpler way?"** RequiredClaims on the identity or grant is believed to do the same job earlier, at sign-in. UNVERIFIED: not tested here.
- **"Can it match a pattern, or a part of the value?"** This template's rule is a `.contains()` test on the claim, not a pattern. The mock compares exactly (an equal string or a list member); whether the real rule is exact, substring or set membership was not measured (UNVERIFIED).
- **"Why did my policy not refuse anything?"** Check its state: per the console documentation (not re-run here, UNVERIFIED) a Candidate is not enforced; only Active is.
- **"Is Real mode in the page?"** No. Real is owner-only: `npm run real` in a terminal reads a local `.env`, mints a token (audience = `DOOR_URL`, scope = `PF_SCOPE`; the token is printed on purpose, the client secret and the Basic value never are) and calls `tools/list`, CountTool and ListIndexTool with no `initialize` handshake. It never creates or deletes policies. That script has never been run against a real PingFederate or door: it copies the call sequence of a scratch script that was run on 2026-11-16, but nothing has re-run it. Assumed, not tested: that your PingFederate client accepts Basic client authentication and your scope, the token endpoint path, that the index it names exists on your door, that HTTP 403 means a grant-layer refusal and that a policy refusal says "denied by policy". The first owner run is the first test, and only its baseline row can be compared with the measured table.
